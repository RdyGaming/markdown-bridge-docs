Security

Last updated: 16 November 2026

Markdown Bridge is built so that there is as little to trust as possible: no vendor server, no stored data, no outbound traffic.

Architecture

  • Runs on Atlassian Forge. The app is a Forge Custom UI app. Atlassian hosts it and isolates it in a sandboxed frame.
  • No backend. There are no app functions, web triggers or remote services. All conversion happens in your browser.
  • No storage. The app does not use Forge storage, databases, cookies or local storage.
  • No egress. The app declares no external hosts. Forge blocks requests to anything not declared, so the app cannot send data outside Atlassian.
  • Acts as you. Every Confluence request is made as the signed-in user. Space and page permissions and restrictions apply as usual.

Permissions the app asks for

ScopeWhy
read:space:confluenceList the spaces you can choose from.
read:page:confluenceRead pages for export and check for existing titles on import.
write:page:confluenceCreate and update pages on import.
read:attachment:confluenceInclude images and files in exports.
write:attachment:confluence, read:content-details:confluenceUpload images referenced by imported Markdown.
read:label:confluence, write:label:confluenceCarry labels through export and import.

The app does not ask for user, group, permission, admin or delete scopes. It cannot delete pages.

Handling untrusted content

  • Imported Markdown is converted to Confluence storage format with every piece of text escaped. Raw HTML in Markdown is never passed through. It is shown as text.
  • Links are limited to http, https, mailto and tel, or to pages and files in the same import. Script and data addresses are removed, including encoded or disguised forms.
  • Exported Markdown escapes page text, blocks unsafe link addresses, and neutralizes content that could break out of comments.
  • Zip files are checked for size, file count and unsafe paths before unpacking.
  • The app's own interface never builds HTML from content. It uses text nodes only, under a strict content security policy with no inline script.
  • Report files guard against spreadsheet formula injection.

Development practices

  • Automated tests cover every conversion, including randomized inputs that must always produce well-formed, allow-listed output.
  • A prelaunch check fails the build if the app declares egress, contains inline script, or writes HTML strings into the page.
  • Three runtime dependencies (Atlassian's bridge, a Markdown parser, a zip library), pinned by lockfile and reviewed on update.
  • No secrets exist in the app. There are no API keys or tokens to leak.

Limits you should know

  • Import with the update option overwrites page bodies. Confluence page history lets you restore earlier versions.
  • Exported files leave Confluence and land on your device. From there, your organization's own controls apply.

Reporting a vulnerability

Email doustd+redheaddev@gmail.com with the subject "Security". Include steps to reproduce. Please do not include real confidential content. We aim to acknowledge reports within 2 business days and to fix confirmed critical issues within the time frames of Atlassian's security bug fix policy for Marketplace apps. We will not take legal action against good-faith research that avoids privacy violations, data destruction and service disruption.
